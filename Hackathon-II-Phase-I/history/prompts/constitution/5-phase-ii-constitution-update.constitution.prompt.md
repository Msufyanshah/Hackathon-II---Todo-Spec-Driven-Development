## Prompt

Phase II Constitution Amendment

Hackathon II – Todo Spec-Driven Development

Applies From: Phase II onward
Status: Active
Amendment Type: Phase Gate Activation
Version: 1.1.0
Effective Date: 2026-01-04

Purpose

This amendment formally activates Phase II architectural, technical, and governance gates as defined in the original Constitution.

Phase II introduces networked, persistent, multi-user web architecture while preserving Spec-Driven Development (SDD) and AI-generated implementation as non-negotiable principles.

Phase II Activation Declaration

The following Constitution principles, previously dormant in Phase I, are now explicitly activated for Phase II.

No Phase III+ principles are activated unless stated.

Activated Capabilities (Phase II)
1. API Architecture (Activated)

The system MUST expose functionality via a RESTful HTTP API

API design MUST follow:

Clear resource naming

Proper HTTP verbs

Predictable request/response schemas

APIs MUST be defined in specification documents before implementation

2. Persistence & Data Modeling (Activated)

The system MUST persist data across application restarts

A database MUST be introduced

Data models MUST be defined in spec.md before implementation

Migration strategy MUST be documented (even if simple)

3. Multi-User Support (Activated)

The system MUST support multiple users

Task data MUST be scoped per user

No shared global task state is permitted

4. Authentication & Authorization (Activated)

Authentication MUST be implemented

Authorization rules MUST be explicit in the specification

JWT-based authentication is the default unless overridden by spec

No hardcoded credentials are permitted

5. Frontend Application (Activated)

A web-based frontend MUST be implemented

Frontend and backend responsibilities MUST be clearly separated

UI behavior MUST trace back to specification requirements

6. AI Code Generation Governance (Reaffirmed)

All source code MUST be generated by approved AI agents
(e.g., Claude Code, Qwen Code)

Manual coding remains strictly prohibited

If output is incorrect, specification refinement is the only correction mechanism

Explicitly Out of Scope (Still Forbidden)

The following remain inactive and MUST NOT appear in Phase II:

AI agents or chatbots as application features

Kubernetes or container orchestration

Event-driven architecture (Kafka, Dapr, etc.)

MCP tools as runtime system components

Cloud-native scaling concerns

Background workers or async pipelines beyond basic API needs

(These are reserved for Phases III–V.)

Phase II Quality Gates

Phase II work MUST satisfy all of the following:

Every API endpoint traces to a Spec requirement

Every database entity traces to a Spec section

Every code artifact traces to a Task ID

No Phase III+ concepts appear in specs, plans, tasks, or code

The system is demonstrable end-to-end (Web UI ↔ API ↔ Database)

Governance Hierarchy (Unchanged)

Constitution
→ Phase Amendment
→ Specification (spec.md)
→ Plan (plan.md)
→ Tasks (tasks.md)
→ Code

Any violation requires explicit amendment, not silent deviation.

Ratification

This amendment is ratified under the authority of the original Constitution and is binding for all Phase II artifacts and implementations.

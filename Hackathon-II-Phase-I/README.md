# Hackathon II - Todo Spec-Driven Development

This repository contains the implementation of a Todo Management System developed using Spec-Kit Plus methodology. The project follows a phased approach, evolving from a console application to a cloud-native, event-driven production system.

## Project Overview

The Todo Management System is being developed through clearly defined phases:

1. **Phase I**: Console-based Todo application
2. **Phase II**: Full-stack web application
3. **Phase III**: AI-powered chatbot interface
4. **Phase IV**: Local Kubernetes deployment
5. **Phase V**: Cloud-native, event-driven production system

## Current Status: Phase I Complete ✅

Phase I has been successfully implemented as a console-only, single-user Todo application with in-memory storage. The system allows a single user to manage personal tasks through CLI commands using in-memory storage.

### Features Implemented

- **Add Task**: Create new tasks with title and optional description
- **View Task List**: Display all tasks with their completion status
- **Update Task**: Modify existing task details
- **Delete Task**: Remove tasks from the list
- **Mark Complete/Incomplete**: Toggle task completion status
- **CLI Interface**: Interactive command-line interface with menu system
- **In-Memory Storage**: All data stored in memory during runtime

### Technical Implementation

- **Language**: Python 3.13+
- **Architecture**: Console-only, single-user application
- **Storage**: In-memory only (no persistence between runs)
- **Pattern**: Clean separation of concerns (models, storage, CLI interface)

### How to Run Phase I Application

1. Ensure Python 3.13+ is installed
2. Navigate to the `phase-1-console` directory
3. Run the application:

   Using UV (recommended):
   ```bash
   uv run src/main.py
   ```

   Alternative (standard Python):
   ```bash
   python src/main.py
   ```

4. Follow the on-screen prompts to interact with the application

## Methodology

This project follows the Spec-Driven Development (SDD) approach:

- **Specification First**: All features are fully specified before implementation
- **AI-Assisted Development**: Code generated via AI agents (Claude Code) from specs
- **No Manual Coding**: Refinement happens by improving the specification
- **Phase-Gated Architecture**: Each phase builds on the previous; phases may not be skipped

## Project Constitution

The project operates under a constitution that defines core principles:

- **Spec-Driven Development First**: No code written until specifications are complete
- **Engineer as Architect**: Human role is system architect and spec author
- **AI-Native & Cloud-Native by Design**: Evolves toward AI agents and cloud architectures
- **Iterative Evolution**: Increments across defined phases
- **No Manual Coding**: All code generated by AI agents
